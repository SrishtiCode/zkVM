# zkvm web visualizers (Phase 8)

Six views into the same pipeline built in Phases 0–7: CPU simulator,
execution trace viewer, AIR visualizer, polynomial viewer, FRI visualizer,
and proof explorer.

## Data flow

There is no mocked data. `crates/viz-export` runs the *real* Rust pipeline
(`isa` + `air` for the CPU-related viewers; `poly` + `merkle` + `fri` +
`transcript` for the polynomial/FRI/proof viewers, proving and verifying a
genuine arithmetic-progression statement) and writes five JSON files to
`web/public/artifacts/`. The React app only ever reads those files — it
never recomputes anything.

```
cargo run -p viz-export --bin export   # from the repo root — writes web/public/artifacts/*.json
cd web
npm install
npm run dev                            # or: npm run build && npm run preview
```

Re-run the `cargo run` step any time the underlying Rust crates change, to
regenerate the artifacts the viewers read.

## Layout

- `src/data/artifacts.ts` — TypeScript types mirroring `viz-export`'s
  `serde` structs exactly, plus `fetch()` helpers.
- `src/useArtifact.tsx` — shared loading/error-state hook.
- `src/viewers/*.tsx` — the six viewers, one file each.
- `src/App.tsx` — tab navigation across them.

## What's next (Phase 9)

Right now the artifacts are static snapshots of one fixed toy program and
one fixed toy statement, regenerated by re-running the Rust binary. Phase
9's WASM build is what turns this into a *live* prover: compiling the
prover to WASM so the browser can generate a fresh proof (for a
user-editable program, even) without a Rust toolchain in the loop at all.
